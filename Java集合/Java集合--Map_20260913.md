## 需重点学习

1. **Java8 扩容机制（第 42 题）**：扩容分两步（长度扩 2 倍 + 迁移数据）；迁移时**不重新计算 hash**，只看原 hash 新增 bit——为 0 留在原索引，为 1 变为"原索引 + oldCap"。这是 1.8 相比 1.7 的核心优化。
2. **树化与扩容的条件对应（第 40 题）**：链表长度达 8 时——数组长度**小于 64** 则扩容（摊薄冲突）；数组长度**已达 64** 才树化。回答时注意不要把两者写反。
3. **HashMap vs Hashtable 完整对比（第 46 题）**：①线程安全/效率；②null 限制（HashMap 允许一个 null key 与多个 null value，Hashtable 不允许）；③默认容量 16 vs 11，扩容 2 倍 vs 2 倍+1；④HashMap 重算 hash，Hashtable 直接用 hashCode。另注意：Hashtable 是 JDK1.0 遗留类，**早于** HashMap（JDK1.2）。
4. **扩容次数计数（第 44 题）**：插入**第 13 个**元素时第一次扩容（16→32），插入**第 25 个**时第二次扩容（32→64），共 2 次；首次 put 初始化分配容量不计入扩容。
5. **哈希冲突解决（第 37 题）**：补开放寻址法（线性探测/二次探测/双重散列）与再哈希法。
6. **ConcurrentHashMap 两代机制（第 52 题）**：1.7 分段锁（Segment，每把锁只锁一段数据）；1.8 摒弃 Segment，用 synchronized + CAS 只锁单个桶。锁粒度远小于 Hashtable 的整表锁。
7. **hash 高低位混合（第 39 题）**：`h ^ (h >>> 16)` 把高 16 位移到低位再异或，让低位带上高位特征、加大随机性。
8. **LinkedHashMap（第 48 题）**：继承自 HashMap，底层仍是哈希桶结构，额外用 before/after 双向链表保持插入顺序，并支持访问顺序逻辑。
9. **Java8 优化完整四条（第 31 题）**：数组+链表改数组+链表/红黑树；头插改尾插；扩容不再重新 hash（位置不变或 +oldCap）；先插入后判断扩容。
