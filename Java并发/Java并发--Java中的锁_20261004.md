## 需重点学习

### 客观错误纠正后的固化记忆（面试中实际出现过）

| 错误表述 | 正确说法 |
| ---- | ---- |
| ReentrantReadWriteLock 基于 Lock 接口实现 | 实现 ReadWriteLock 接口；内部 ReadLock/WriteLock 才实现 Lock |
| 公平锁把锁"递给"最早等待的线程 | 公平是当前线程"不抢"→入队，AQS 引擎按队列顺序唤醒队首 |
| 非公平：释放者可能再拿（只这一个角度） | 完整：等待者之间也不按顺序（后申请的可能插队），全凭手气 |
| 第 88 题用"减少上下文切换"当理由 | 这是结果，机制是"公平强制入队+唤醒（付状态转换），非公平先 CAS 直抢（跳过转换）" |
| 第 93 题用"读时穿插写造成安全问题"解释禁升级 | 禁升级的真正理由是升级行为本身死锁（两线程同时升级互等） |
| 第 84 题只说"AQS 已实现/自己实现" | 三类方法完整口径：3 工具（state 操作）+5 钩子（tryAcquire 等）+9 模板（acquire 等） |

### 反复出现的弱点（需专门固化）

Lock 相比 synchronized 的五大优势——本轮内三次未主动答全，必须连记：
1. 公平锁可选（ReentrantLock 构造传 true；synchronized 只非公平）
2. 可响应中断（lockInterruptibly；synchronized 不能）
3. tryLock 尝试获取（立即返回 / 超时返回）
4. 多 Condition 队列（newCondition）
5. 多种锁实现（读写锁、可重入锁等扩展性）
