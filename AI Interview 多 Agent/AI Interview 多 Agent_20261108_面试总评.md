# AI Interview 多 Agent 项目模拟面试评估

- **日期** 2026 年 11 月 8 日
- **范围** 系统架构与多 Agent 设计、RAG 多路召回与检索、RAG 评估体系、Agent 记忆系统、动态难度调节与出题策略、Skill 技能系统、MCP 与工程化、拓展优化题，共 40 题。
- **作答记录** 32 题有实质作答，其中第 37、39 题是在看过整理版后作答。第 13、36 题只看了参考答案，6 题跳过。重答和补答记录在对应题目下。评价依据是本次作答与题库，项目事实、题库口径和扩展方案分别表述。

## 整体表现

能把正式面试串成一条完整的链路，从岗位与简历分析、出题方向规划、题库检索，到逐题面试、评分和复习规划。对多 Agent 的职责划分、向量检索和 BM25 的互补、按用户隔离题库，以及题库优先与模型兜底等问题，能说明设计动机和数据如何流转。第 37 题在讲解后说出了答案队列的等待与恢复过程。第 39 题在看过整理版后，能用集中交卷解释模型请求高峰，也能提出保存面试状态、释放等待线程、收到答案后再调度的方案。

主要失分点出现在**机制边界、异常路径和验证步骤**。例如，能说出 RRF 的公式，但把分数尺度不同当成了舍弃 RRF 的原因。能说出做过召回率评估，但把查询词说成了真值标签。能说明提示词应约束 JSON 格式，但缺少解析已经失败时的运行时兜底。能讲清流程大意的题，往往只需要补一条精确的触发条件，或一句说明如何验证。

## 需重点学习

1. **先把 RAG 指标和重排机制说准。** 用同一个例子说明查询词、相关题目 ID、Recall@K 和 MRR。练习用一句话说清 RRF 依据排名融合，再用一句话讲清排序失败时的回退。把“所有候选都保留”和“相关候选进入前 K”作为两个不同的验证点。
2. **把容易串用的条件整理成一张口述卡片。** 分别列出近期聊天窗口、长期薄弱点记录与移除、动态难度判定、追问条件。数字按相应题库或当前配置核对。讲薄弱点 30 天过期时，说明过滤发生在哪一步。
3. **把工程题按触发、执行和后续处理讲完整。** WebSocket 题重点说清谁在等、谁入队、为什么接收线程还在运行。题库去重题先按 Redis Key 是否存在分类，再判断哈希，最后说明何时更新记录。百人并发题用“模型限流与排队、面试状态可恢复、真实节奏压测”组织，并以提交答案到收到评分的耗时验证体验。
4. **把项目困难整理成一个可追问的完整案例。** 用“发现指标下降、对比候选定位、调整重排、复测验证”串起来。只引用能够说明实验口径的数据，并把未来的扩展设计与已经完成的项目工作分别表述。
